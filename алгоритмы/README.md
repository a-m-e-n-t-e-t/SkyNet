# SkyNet — Алгоритмы заполнения карточек с помощью ИИ

> Пошаговые алгоритмы для ИИ (LLM) по заполнению карточек базы знаний SkyNet.
> Основание: система шаблонов [`шаблоны/`](../шаблоны/README.md) (21 шаблон, схемы v10.1–v11.0, §9–§15a промпта) и практика наполнения (1783 карточки в четырёх доменах).
>
> **Шаблон отвечает на вопрос «что должно быть в карточке». Алгоритм отвечает на вопрос «как ИИ её создаёт»: порядок действий, источники данных, самопроверка, типичные ошибки.** Используются вместе: алгоритм типа + шаблон типа + исходные данные.

## Карта зависимостей: порядок создания связанных карточек

Карточки связаны ссылками, поэтому ИИ создаёт их в порядке зависимостей — сначала то, на что ссылаются:

```text
06 стандарт ────┐
07 группа ──────┼──→ 01 материал ──┐
                     03 технология ─┼──→ 02 изделие ──→ 04 модель ──→ 05 реализация
08 произведение ──→ 09 фантастический материал ──→ 04 модель
01|02|03 предок ──→ 10 ии-обёртка
любые карточки  ──→ 11 списки (финальный шаг, генератором)
```

- Материал обязан ссылаться на группу (F7 = 1.0) и может — на стандарты (F6): группы и стандарты создаются раньше материалов.
- Изделие ссылается на материалы и технологии (B-BOM): они создаются раньше изделий.
- Модель ссылается на произведения (`произведения: [work_id]`) и в компоновке P028 — на изделия.
- Реализация ссылается на модель и используемые изделия/технологии/материалы.
- Обёртка ссылается на предка и не изменяет его; списки обновляются после всех карточек.

## Как использовать алгоритм с ИИ

### Сборка контекста (что дать модели)

1. Этот README — карта зависимостей и общие принципы.
2. [`00_универсальный_алгоритм.md`](00_универсальный_алгоритм.md) — общий конвейер для любого типа.
3. Алгоритм нужного типа (01–11).
4. Шаблон из `шаблоны/` — структура полей и чек-лист.
5. Исходные данные: текст пользователя, результаты веб-поиска или канон произведения.

### Промпт-паттерн (шаблон запроса к ИИ)

```text
Ты — инженер базы знаний SkyNet. Создай карточку <тип> «<имя>».
Следуй алгоритму <N_алгоритм_типа> по этапам; структуру полей бери строго из
шаблона <шаблон>. Правила: enum — только из допустимых списков (§0.2);
каждое число — с источником (§22); значение вносится один раз — в front
matter (F26); null — только с обоснованием. Сначала выведи план
(классификация, id, состав полей), затем готовый файл целиком, затем пройди
чек-лист шаблона и чек-лист алгоритма и исправь найденные ошибки.
```

### Цикл «заполнение → самопроверка → исправление»

1. ИИ заполняет карточку по алгоритму (этапы 1–8).
2. Сам сверяет с ДВУМЯ чек-листами: шаблона (структура) и алгоритма (процесс).
3. Запуск валидаторов: `sync_materials.py --check`, `generate_lists.py --check`, `validate_templates.py` (шаблоны), `pre-commit-hook.py` (карточки).
4. Замечания исправляются в той же карточке; повторная сверка.

### Пакетное наполнение

При создании серии карточек (например, 20 материалов из одного источника): создавать по одной, списки обновить один раз в конце, закоммитить одним коммитом `feat(материалы): +20 карточек — <тема>`.

## Общие принципы (полностью — в универсальном алгоритме)

- **F26 «одно значение — одно место»**: числа и enum — только в front matter; тело — повествование.
- **Enum-дисциплина** (§0.2): недопустимое значение = блокировка.
- **Прозрачность источников** (§22): у каждого числа — источник; «phantom»-значения запрещены.
- **Заполненность** (§24): 100% полей, без `TODO/TBD/FIXME`.
- **TRL** (§32): `фантастический | теоретический | лабораторный | ограниченный | промышленный | ии_проект | устаревший`; материалы v10.1 — числовой `доступность_tlr` 0–9.
- **Имена** (§15a.1): строчные, пробелы → `_`, 3–80 символов, без `/\ : * ? " < > |`; сводные файлы — с `_`.
- **Коммиты** (§15a.2): `feat|fix|docs|refactor|verify|chore|backup(<область>): <описание>`.

## Инструменты

| Скрипт | Что делает | Когда запускать |
|---|---|---|
| `scripts/validate_templates.py` | валидация папки `шаблоны/` (21 + README) | после изменения шаблонов |
| `scripts/sync_materials.py` | пустые шаблоны материалов для ссылок без карточек; `--check` — отчёт | перед списками (встроен в CI) |
| `scripts/generate_lists.py` | генерация 11 списков + зеркал + реестра; `--check` — CI-сверка | после коммита карточек (встроен в CI) |
| `scripts/pre-commit-hook.py` | валидация карточек развёрнутой базы | перед коммитом карточек |

CI `.github/workflows/update-lists.yml` запускает синхронизацию и генерацию списков автоматически при пуше карточек.
