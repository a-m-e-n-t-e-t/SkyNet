# 03. Алгоритм заполнения карточки технологии (§12.2, схема v11.0)

> Карточка технологии: `реальные данные/технологии/<id>.md`. Шаблон: `шаблоны/шаблон_технологии.md`.
> Ключевое правило v6: параметры режима — ОДИНОЧНЫЕ значения (номиналы); окно процесса — в поле `допуски`.

## Предусловия

1. Материалы для процесса и оборудование (изделия) существуют или создаются раньше (алгоритмы 01, 02).
2. Дедупликация: `реальные данные/технологии/_список_технологий.md` и зеркало `работа и и/технологии/`.

## Этап 1. Классификация

1. `id: tekhnologia_<имя>` (пример: `tekhnologia_cvd`); имя файла — строчные, пробелы → `_` (cvd.md, galvanika.md).
2. `категория` — enum: `обработка|сборка|испытание|модификация|прочее`.
3. `область_применения` — список (микроэлектроника, нанесение_покрытий...).
4. `прототип` — id технологии-прототипа; нужен, только если заполняются `наследуемые` (v9.12 — согласованность наследования).

## Этап 2. Параметры режима (7 ключевых полей, v6)

`основные` — каждое поле ОДНО значение-номинал (НЕ диапазон!):

- `температура_режима_C`, `давление_Pa`, `время_цикла_s`, `кпд_pct`, `производительность_шт_ч`, `потребление_энергии_kWh`, `потребление_воды_L`.

Окно процесса (например, 950–1050 °C) — в `дополнительные.допуски`. Ограничения — в `дополнительные.ограничения`. Номинал = типичный режим зафиксированного варианта процесса; разброс по режимам — отдельными карточками-вариантами, а не диапазоном.

## Этап 3. Наследование

`наследуемые` (`стандартные_параметры`, `сертификация`) — только `{computed_from: прототип}` при заполненном `прототип`; иначе блок не указывается вовсе.

## Этап 4. Связи

- `оборудование` — ссылки на карточки изделий-оборудования (существуют!).
- `материалы_для_процесса` — ссылки на карточки материалов.

## Этап 5. Метаданные (v11.0)

`версия_схемы: 11.0`; `версия: реальная`; `статус_реальности: real`; `доступность` — enum §32; `статус`; `источник {тип, url, дата}`; `создано/обновлено`.

## Этап 6. Тело карточки

1. `## Описание` — что за процесс, физический принцип, для чего применяется, отличия от альтернатив (+ полное наименование как в CSV).
2. `## Входные ресурсы` — таблица «Ресурс | Параметры | Количество» (соответствует `материалы_для_процесса`).
3. `## Операции` — нумерованные шаги процесса (1. 2. 3. ...) с физикой каждого шага.
4. `## Выходной результат` — состояние, качество, типичные дефекты.
5. `## Оборудование` — ссылки на карточки изделий.
6. `## Ограничения и допуски` — повествование; значения — в front matter.
7. `## Альтернативные технологии` — когда предпочтительна альтернатива.
8. `## Источники`, `## Чек-лист`.

## Этап 7. Обратные связи

- Изделия, использующие технологию (`технологии_частей`), — упомянуть их в теле/«Оборудовании» при уместности.
- Карточки материалов, участвующих в процессе, — проверить их разделы «Технологии получения».

## Этап 8. Самопроверка

- [ ] Параметры режима — одиночные значения; окно — в `допуски` (v6).
- [ ] `материалы_для_процесса` и `оборудование` ссылаются на существующие карточки.
- [ ] Заполнены `наследуемые` → указан `прототип`.
- [ ] Числа имеют источники (§22); категория — из enum.
- [ ] F26: числа не дублируются в теле.

## Этап 9. Валидация и коммит

```bash
python3 scripts/generate_lists.py
```

Коммит: `feat(технологии): tekhnologia_<имя> — <название>`.

## Типичные ошибки ИИ

- Диапазон в `температура_режима_C` вместо номинала (v6).
- Окно процесса не перенесено в `допуски`.
- `наследуемые` без `прототип`.
- Шаги «Операций» без физики (перечислен список, а не процесс).
- Оборудование из несуществующих карточек.
