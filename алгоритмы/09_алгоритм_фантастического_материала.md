# 09. Алгоритм заполнения карточки фантастического материала (§12.3a, схема v10.0)

> Материал из канона произведений: `фантастические данные/материалы/<id>.md`. Шаблон: `шаблоны/фантастического_материала.md` (в `шаблоны/`).
> ГЛАВНОЕ ОТЛИЧИЕ от реального материала (алгоритм 01): ЗАПРЕЩЕНЫ реальные свойства и числа.

## Запреты (§12.3a — проверяются в первую очередь)

1. `химический_состав: не_определён` — НЕ выдумывать формулу, даже «правдоподобную».
2. Реальные физические свойства как собственные — ЗАПРЕЩЕНЫ (никаких плотностей, прочностей, температур плавления).
3. Числа в `канон_фактах` — ЗАПРЕЩЕНЫ (только качественные факты: «неуязвим для стрелкового оружия», а не «прочность 5000 МПа»).
4. Поле `основан_на` — НЕ используется; только `вдохновлён_реальным` (мера «вдохновения», не совпадения свойств).
5. Вместо групп свойств — `канон_факты` без чисел.

## Этап 1. Канон

1. `id: material_<имя>`; `тип: материал`; `класс: фантастический_материал` (фиксировано).
2. `канон_источник` — произведение, задающее канон (проверить карточку work_NNN, алгоритм 08).
3. `вдохновлён_реальным` — id реального аналога (необязательно, но ценно; связь с доменом `реальные данные/`).

## Этап 2. Структура (упрощённая)

`структурные_варианты` — ровно ОДИН вариант:

```yaml
структурные_варианты:
  - id: <имя>_основной
    вариант: н_д
    существует: да
    основной: да
    описание: '<канонное описание структуры/состояния, если оно описано в произведении>'
```

Никаких механических/термических/химических блоков — их место занимают `фантастические_свойства` и `канон_факты`.

## Этап 3. Фантастические свойства и факты

1. `фантастические_свойства` — список: `['самовосстановление', 'жидкая морфология', ...]` — из канона, без чисел.
2. `канон_факты` — список фактов БЕЗ чисел; каждый — с привязкой к канону (эпизод/сцена/страница — в Источниках тела).
3. `исследовательская_группа: требует_верификации` (фиксировано — реальных исследований нет).

## Этап 4. Метаданные

`версия_схемы: "10.0"` (строкой!); `реальность: канон`; `доступность_tlr: 0`; `статус: извлечено`; `источник {тип: пользовательский_ввод|веб_поиск|вывод_ии, проверено}`; `создано/обновлено`; `ии_перепроектирован: нет`.

## Этап 5. Тело карточки

1. `# <Название>` + цитата «Материал из канона» из шаблона.
2. `## Описание (канон)` — что это в произведении, чем известен, ключевые особенности.
3. `## Канонные факты` — список = полю `канон_факты`.
4. `## Реальный аналог` — чем похож, чем отличается; по какой мере это «вдохновение», а не совпадение свойств.
5. `## Источники` — `канон_источник`: эпизод/страница/главка.

## Этап 6. Обратные связи

- В карточке произведения — `материалы_в_произведении` (v11.0, двусторонняя связь).
- Список `фантастические данные/материалы/_список_фантастических_материалов.md` — генератором.

## Этап 7. Самопроверка

- [ ] Нет чисел в свойствах и фактах; нет выдуманной формулы.
- [ ] Ровно один структурный вариант с `вариант: н_д`.
- [ ] `доступность_tlr: 0`; `реальность: канон`.
- [ ] `вдохновлён_реальным` указывает на существующую карточку (если заполнен).
- [ ] Канон-факты привязаны к произведению (источники в теле).

## Этап 8. Валидация и коммит

```bash
python3 scripts/generate_lists.py
```

Коммит: `feat(фантастические материалы): material_<имя> — <название>`.

## Типичные ошибки ИИ

- Придумана химическая формула (запрещено §12.3a).
- Числовые свойства «для полноты» (запрещены; это не реальный материал).
- Скопированы свойства реального аналога как собственные.
- Несколько структурных вариантов вместо одного `н_д`.
- Поле `основан_на` вместо `вдохновлён_реальным`.
