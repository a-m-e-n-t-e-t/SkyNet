# 02. Алгоритм заполнения карточки изделия (§12.1 + §12.6 + §12.7, схема v11.0)

> Изделия и части уровней 1–4: верхний уровень — `реальные данные/изделия/<подсистема>/<имя>/_index.md`; части — `.../<имя>/<часть>.md`.
> Декомпозиция обязательна (v9.28); дочерние части наследуют подсистему и подтип от родителя.
> Критичные метрики: F8 (подтип), F15g (габариты), F26, F27e (технологии частей), F29 (наследуемые материалы), F62 (оптимальная структура ≥ 0.90, P062).

## Предусловия

1. Справочники под рукой: подсистемы §11.0 (13), подтипы §11.4 (146).
2. Карточки материалов и технологий, на которые ссылается B-BOM, существуют (иначе — сначала алгоритмы 01/03 или пустой шаблон через sync_materials).
3. Дедупликация: `реальные данные/изделия/_список_изделий.md` и зеркало `работа и и/изделия/`.

## Этап 1. Классификация (до всех данных)

1. `категория` — enum: `машиностроение|электроника|оптика|энергетика|прочее`.
2. `подсистема` — одна из 13 §11.0; = имя папки-классификатора. Обязательно для ВСЕХ изделий и частей.
3. `подтип` — один из 146 §11.4 или `прочее` (F8). Подтип = принцип, а не параметр (P020): «модуль_пельтье», а не «40×40 мм».
4. `уровень_иерархии` — `верхний|промежуточный|неделимый`; `уровень_номер` 1–4.
5. `id`: верхний — `izdelie_<имя>`; часть — `часть_<родитель>_<имя>`; `количество` — N идентичных копий (масса/габариты — за ОДИН экземпляр, F26).
6. `стандарты`, `исследовательская_группа` — опционально для изделий (обязательно для материалов).

## Этап 2. Планирование декомпозиции (v9.28)

1. Составить дерево: изделие → части → ... до неделимых; глубина ≤ 4 уровней.
2. Для каждой части определить: роль, материал, технология обработки.
3. Оформить дерево как mermaid-граф (`graph TD`) для раздела «Декомпозиция».
4. Структура папки: `<имя>/_index.md` (верхний уровень) + `<имя>/<часть>.md`.

## Этап 3. B-BOM: материалы частей (F62 — сердце карточки)

Для каждой части:

1. `часть` — id части; `материал` — id СУЩЕСТВУЮЩЕЙ карточки материала.
2. `форма` — форма применения: `модуль_пельтье`, `несущая_плата_PCB`, `корпус`...
3. `доля_массы` — 0–1; сумма долей всех частей ≈ 1.0 (проверить сложением!).
4. `оптимальная_структура` (обязательно, F62 ≥ 0.90):
   - `вариант_id` — ПРОЧИТАТЬ `структурные_варианты[].id` из карточки материала и взять существующий (машиночитаемая связь v10.1, НЕ свободный enum!);
   - `обоснование_выбора` — физика применения: циклическая нагрузка → поли-; крип > 700 °C → моно-; ВЧ-магнитопровод → аморфный; UD-укладка → композиционный;
   - `источник_обоснования` — `web_search|kb_lookup|computed_from_physics`.
5. `наследуемые_материалы` — агрегация (F29): материал → части → `суммарная_доля_массы` + `источники_частей`; оптимальная_структура НЕ дублируется.

## Этап 4. Технологии частей (F27e)

`технологии_частей`: часть → технология (существует) → `доля_использования` → `материалы_для_процесса` (роль: `обрабатываемый`).

## Этап 5. Физическое воплощение (v6 — по одному значению)

1. `основные`: `масса_kg`, `габариты_mm {l, w, h}` (три размера — не диапазон), `выработка_энергии_W`, `выработка_тепла_W` — конкретного изделия, номиналы.
2. `наследуемые` — ТОЛЬКО `computed_from`, числами не заполняются: масса = SUM(дочерних × доля), прочность = MIN(дочерних) (weakest link), энергопотребление = SUM(пиковых), тепловыделение = SUM, стоимость = SUM, lifetime = MIN.
3. `дополнительные`: `цена_usd`, `форм_фактор` (пример: M.2-модуль 2280), `обоснование_габаритов` — V ≥ ΣV(деталей) × 1.15 (F15g).

## Этап 6. Масштабируемость (§12.6, если применимо)

`режим`: `масштабируемая|квантуемая|фиксированная`; `параметры` (масса_kg, мощность_W...); `пределы` min/max; `шаг` (null = непрерывно, список = ряд, число = дискрет); `закон_масштабирования`: `линейный|квадратичный|кубический|кусочно`; `ограничивающие_части` (часть + причина: порт/размер/техпроцесс); `scaling_type`: `количественный|качественный` (P040); `соединители` (кабель_силовой|шланг_гидравлический|шина_данных|разъём).

## Этап 7. Метаданные (v11.0) и тело

Метаданные: `версия_схемы: 11.0`; `версия: реальная`; `статус_реальности: real`; `доступность` — enum §32; `статус`; `ии_перепроектирован: нет`; `источник {тип, url, дата}`; `создано/обновлено`.

Тело: `## Описание` (+ полное наименование как в CSV; для части — роль в составе родителя), `## Состав` (аннотированный перечень: роль и назначение, БЕЗ дублей id и долей), `## Декомпозиция` (mermaid), `## Используемые технологии` (ссылки), `## Используемые материалы` (ссылки; выбор варианта — в `вариант_id`, в теле не дублируется), `## Принцип работы`, `## Варианты реализации` (только верхний уровень), `## Сравнение с реальным аналогом` (только `версия: ии-улучшенная`), `## Источники`, `## Чек-лист`.

## Этап 8. Согласование иерархии (двусторонние связи)

- Родитель: `дочерние_части` содержит id каждой части. Часть: `родитель` = id родителя; подсистема и подтип = родительские.
- Часть → материал/технология: обратные ссылки в их карточках («Применение в изделиях» / упоминание).
- Для `ии-улучшенной` версии — блок §12.7 в конце файла (предок, улучшения, real_check) либо отдельная обёртка по алгоритму 10.

## Этап 9. Самопроверка

- [ ] Подсистема и подтип заполнены и совпадают с папкой-классификатором (F8).
- [ ] Декомпозиция согласована: `родитель` ↔ `дочерние_части` ↔ mermaid-граф ↔ фактические файлы.
- [ ] `вариант_id` каждой части существует в `структурные_варианты` карточки материала (F62).
- [ ] Сумма `доля_массы` ≈ 1.0.
- [ ] Габариты обоснованы: V ≥ ΣV(деталей) × 1.15 (F15g).
- [ ] Все ссылки ведут на существующие карточки.
- [ ] F26: числа не дублируются в теле; `наследуемые` — только computed_from.

## Этап 10. Валидация и коммит

```bash
python3 scripts/generate_lists.py
```

Коммит: `feat(изделия): izdelie_<имя> — <название> (+ N частей)`.

## Типичные ошибки ИИ

- Подтип пропущен или параметр вместо принципа (F8/P020).
- `вариант_id` придуман, а не прочитан из карточки материала (битая связь F62).
- Доли массы не сходятся к 1.0.
- `наследуемые` заполнены числами вместо `computed_from`.
- Габариты без обоснования (F15g).
- mermaid-граф расходится с `дочерние_части`.
- Изделие-часть положено не в папку родителя / подсистема части ≠ родительской.
