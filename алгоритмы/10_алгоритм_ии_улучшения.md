# 10. Алгоритм заполнения карточки-обёртки ИИ-улучшения (§12.7, схема v11.0)

> Дельта-обёртка ИИ-улучшения: `работа и и/материалы/<оригинал>__ии.md`, `работа и и/технологии/<оригинал>__ии.md`; обёртки-изделия (верхний уровень и части): `работа и и/изделия/<подсистема>/<оригинал>__ии/_index.md`.
> Шаблон: `шаблоны/ии_улучшения.md` (в `шаблоны/`).
> ГЛАВНЫЙ ПРИНЦИП: обёртка хранит ТОЛЬКО дельту — `предок` + `улучшения` + `real_check`. Свойства предка НЕ копируются (F26: одно значение — одно место; свойства читаются из карточки предка).

## Предусловия

1. Карточка-предок существует и заполнена (не пустой шаблон).
2. Сформулирована цель улучшения: масса / прочность / цена / технология / ресурс — против КОНКРЕТНЫХ свойств предка.

## Этап 1. Прочитать предка полностью

Карточка предка + (для материала) его `структурные_варианты` с id и свойствами + (для изделия) B-BOM `материалы_частей` и `технологии_частей`. Улучшение предлагается ПРОТИВ фактических свойств предка, а не «вообще».

## Этап 2. Сгенерировать улучшения (≥1 запись)

Каждая запись `улучшения`:

- `тип` — enum: `замена_материала|замена_технологии|добавление_технологии|оптимизация_геометрии|замена_параметра`;
- `что` — что изменено (конкретно: «корпус: ss_316l → ti-6al-4v, вариант_id <id>»);
- `причина` — ФИЗИЧЕСКОЕ обоснование, не «стало лучше»: «усталостная прочность варианта X при циклической нагрузке выше» / «плотность ниже при равной текучести → минус масса»;
- `источник` — откуда изменение (расчёт / веб-поиск / физика);
- `эффект_масса` — оценка эффекта по массе (опц.).

Критерий качества: каждое улучшение ПРОВЕРЯЕМО — называет свойство предка, новое решение и физический механизм. Если механизм назвать нельзя — это не улучшение, а фантазия (кандидат на отклонение в real_check).

## Этап 3. real_check (ЧЕСТНО)

`статус`: `проверен|требует_проверки|отклонён`; `метод` — чем подтверждено: итерации расчёта, источники. Не ставить `проверен` без реальной сверки с источниками/расчётом — статус проверяется по §22.

## Этап 4. Имена и размещение

- `id` = `<id предка>__ii` (латиница, суффикс `__ii`); файл = `<оригинал>__ии.md`.
- `тип` = типу карточки-предка (`материал|изделие|технология`) — фиксируется.
- `предок` — id предка (без суффикса); `предок_путь` — путь к карточке предка (без .md).

## Этап 5. Метаданные

`версия_схемы: 11.0`; `версия: ии-улучшенная` (фиксировано для `работа и и/`); `статус_реальности: ии-улучшенная` (только это значение в домене); `доступность` — enum §32; `ии_перепроектирован: да`; `источник.тип: вывод_ИИ`; `создано/обновлено`.

## Этап 6. Тело карточки

1. `## Предок` — ссылка на карточку предка (относительный Markdown-путь, §15a.3).
2. `## Что улучшено` — повествовательное раскрытие `улучшения`: физика изменения, мотив, ожидаемый эффект; значения из front matter не повторяются.
3. `## Проверка реальности` — раскрытие `real_check`: чем подтверждено, что осталось проверить.
4. `## Источники`, `## Чек-лист` (из шаблона).

## Этап 7. Границы (что НЕ делать)

- Предок НЕ изменяется (остаётся `real`; `статус_реальности` предка не трогать).
- Свойства предка НЕ копируются в обёртку (F26 — дельта).
- Служебные обёртки моделей (вариант D v9.40, `izdelie_SkyNet-<имя>`, `scripts/generate_wrapper_izdeliya.py`) — ПОЛНЫЕ карточки для поддержки декомпозиции, НЕ дельты §12.7; этим алгоритмом не создаются.
- Зеркала списков `работа и и/<тип>/` обновить в ТОМ ЖЕ коммите (`_список_*.md` — только `<оригинал>__ии.md`).

## Этап 8. Самопроверка

- [ ] id = id предка + `__ii`; файл = `<оригинал>__ии.md`; размещён в `работа и и/<тип>/`.
- [ ] Предок существует; `тип` обёртки = типу предка; свойства предка НЕ скопированы.
- [ ] `улучшения` ≥1 записи: тип/что/причина/источник; `real_check` заполнен честно.
- [ ] `версия` = `ии-улучшенная`; `статус_реальности` = `ии-улучшенная`; `ии_перепроектирован` = `да`.
- [ ] Предок остался без изменений; зеркала списков обновлены.

## Этап 9. Валидация и коммит

```bash
python3 scripts/generate_lists.py
```

Коммит: `feat(работа и и): <оригинал>__ии — <суть улучшения>`.

## Типичные ошибки ИИ

- Копирование свойств предка в обёртку (нарушение F26 — самое частое).
- Улучшение без физического механизма («оптимизировали на 20%»).
- `real_check: проверен` без фактической сверки.
- Изменена карточка предка (предок обязан оставаться `real`).
- Служебная обёртка модели создана по шаблону §12.7 (для них — полный шаблон изделия, вариант D).
- Зеркало списка `работа и и/` забыто в коммите.
