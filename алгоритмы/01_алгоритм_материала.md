# 01. Алгоритм заполнения карточки материала (§12.3, схема v10.1)

> Карточка реального материала: `реальные данные/материалы/<id>.md`. Шаблон: `шаблоны/шаблон_материала.md`.
> Критичные F-метрики: F5 (структурные варианты = 1.0 — блокировка при отсутствии), F7 (группа = 1.0), F6 (стандарты), F26 (анти-дублирование), F62 (на вариант ссылается изделие через `вариант_id`).

## Предусловия

1. Карточка исследовательской группы существует (F7 — поле обязательно). Если нет — сначала алгоритм 07.
2. Дедупликация выполнена (этап 2 универсального алгоритма): список `реальные данные/материалы/_список_материалов.md`, ALIASES в `scripts/sync_materials.py`, пустые шаблоны (`статус: пустой_шаблон`). Пустой шаблон заполняется, а не создаётся заново.

## Этап 1. Классификация и идентификация

1. `id: material_<имя>` — KEBAB-CASE (пример: `material_ptfe`).
2. `класс` — enum из 8: `металл|сплав|керамика|полупроводник|полимер|композит|радиоизотоп|прочее`. Материал вне enum (урок v1: 31 карточка) → ближайший допустимый класс, старое значение — в комментарий `# было: ...`.
3. `химический_состав` — рациональная формула, состав, CAS-номер при наличии. НЕ выдумывать: только из источника (производитель, справочник, веб-поиск).

## Этап 2. Структурные варианты (F5 — без них карточка блокируется)

Шаг 1 — составить СПИСОК вариантов, прежде чем заполнять свойства: спросить «в каких структурных состояниях существует материал?» — полиморфы (α/β-фазы), моно-/поликристалл, аморфная фаза, компоненты композита.

Шаг 2 — правила оформления:
- ≥1 варианта; ровно ОДИН с `основной: да` (его свойства обязательны);
- `существует: да|нет` — «нет» = справочный вариант, свойства не заполняются;
- `вариант` — enum из 14: `монокристаллический|поликристаллический|микрокристаллический|полукристаллический|нанокристаллический|аморфный|стеклокерамика|квазикристаллический|жидкокристаллический|композиционный|жидкость|газ|молекулярный_кристалл|не_определён` (микро — зерно 0,1–10 мкм; нано — <100 нм);
- `id` варианта — kebab_case, уникален: на него ссылается `оптимальная_структура.вариант_id` карточки изделия (F62, v10.1).

Шаг 3 — свойства каждого варианта (v6: каждое число — ОДНО значение-номинал):

- `кристаллография` (кристаллические варианты): сингония (7), структурный_тип (ГЦК/ОЦК/ГПУ/рутил/перовскит/...), пространственная_группа, размер_зерна_мкм, текстура;
- `механические`: плотность_кг_м3, предел_прочности_МПа (UTS), предел_текучести_МПа, модуль_юна_ГПа, коэффициент_пуассона, относительное_удлинение_pct, ударная_вязкость_Дж_см2, усталостная_прочность_МПа (10^7 циклов), твердость_hv/hrc/мооса, коэффициент_демпфирования;
- `термические`: температура_плавления_C, теплопроводность_вт_м_к, теплоёмкость_Дж_кг_К, ктр_1_К, `минимальная_рабочая_температура_C` + `максимальная_рабочая_температура_C` (ПАРА полей, не диапазон; α- и β-фазы различаются!);
- `электрические_магнитные` (электропроводность_S_м, магнитная_проницаемость), `прочее` (пористость_pct);
- `химическая_стойкость` — 9 сред, каждая — enum `высокая|средняя|низкая|нестойкий|не_определён`: `вода_и_влажность`, `кислоты`, `щёлочи`, `солевой_туман`, `растворители_и_топливо`, `высокотемпературное_окисление`, `уф_излучение`, `радиация`, `биоповреждения` + число `скорость_коррозии_мм_год` (опц.);
- `экономика` — ЦЕНА ОТНОСИТСЯ К КОНКРЕТНОМУ ВАРИАНТУ: `цена_usd_kg`, `форма_поставки` (слиток|порошок|лист|фольга|волокно|плёнка|заготовка...), `условия_цены` (FCA|EXW|объём партии). Моно- и поликристалл, волокно и порошок различаются в разы;
- `источник_url` — источник свойств варианта.

Разброс свойств от термообработки — НЕ в варианте: в карточке технологии или `варианты_по_применению`.

## Этап 3. Применения и сравнение структур

- `применения_структур` — ОБЯЗАТЕЛЬНО при ≥2 применениях с разными оптимальными структурами (P062): ключ-применение → `вариант_id` (ССЫЛКА, свойства не копируются) + описание + конкретные узлы.
- `сравнение_структур` — обязательно при ≥2 промышленно доступных вариантах: ключ — имя варианта → `вариант_id`, `когда_выбирать`, `источник_url`.

## Этап 4. Связи

- `исследовательская_группа` — обязательно (F7): id существующей группы; `требует_верификации` — временная заглушка с планом закрытия.
- `стандарты` — опционально (F6): ссылки на существующие карточки стандартов.

## Этап 5. Метаданные (v10.1 — отличается от v11.0!)

```yaml
метаданные:
  версия_схемы: 10.1
  версия_данных: реальная        # реальная | ии-улучшенная
  реальность: реальный           # реальный | канон
  доступность_tlr: 7             # ЧИСЛО 1–9 (не enum!)
  статус: извлечено              # извлечено | верифицировано | оптимизировано
  ии_перепроектирован: нет
  источник:
    тип: пользовательский_ввод   # пользовательский_ввод | веб_поиск | вывод_ии
    разбор: <канон|веб_поиск|вывод_ии|пользовательский_ввод_плюс_веб_поиск>
    url: '<URL если веб_поиск>'
    проверено: ГГГГ-ММ-ДД
  создано: ГГГГ-ММ-ДД
  обновлено: ГГГГ-ММ-ДД
```

Не смешивать с блоком v11.0 (`версия`, `статус_реальности`, `доступность`-enum, `источник.дата`).

## Этап 6. Тело карточки

1. `# <Название>` + цитата-напоминание о F26 (оставить из шаблона).
2. `## Описание` — что это, сильные/слабые стороны; резюме вариантов БЕЗ чисел; «доступен только <X>-вариант» — если вариант один. Полное наименование (как в CSV).
3. `## Структура и варианты` — таблица: Вариант | id | Основной? | Когда выбирать (критерии, не числа).
4. `## Эксплуатационные особенности` — качественно: температурные границы, стойкость, обработка (значения — в front matter).
5. `## Технологии получения` — ссылки на карточки технологий.
6. `## Применение в изделиях` — обратные ссылки из карточек изделий (этап 7): id части — форма/роль (вариант: id).
7. `## Аналоги и заменители`, `## Источники` (что каждый источник подтвердил).

## Этап 7. Обратные связи

- Найти изделия, использующие материал: `материалы_частей`, `наследуемые_материалы`, `материалы_для_процесса`, ссылки в текстах карточек → перенести в «Применение в изделиях».
- Если материал раньше упоминался ссылками без карточки — у пустого шаблона (sync_materials) уже есть блок «упомянут в» — перенести его в тело.

## Этап 8. Самопроверка

- [ ] F5: ≥1 структурный вариант; ровно один `основной: да`.
- [ ] F7: группа указана (или план закрытия заглушки).
- [ ] Все enum из списков: класс 8, вариант 14, стойкость 5.
- [ ] Каждое число — с источником; null — обоснованы в теле.
- [ ] v6: нет `{min, max, nominal}`; рабочие температуры — пара именованных полей.
- [ ] Цена — у каждого варианта отдельно; форма поставки указана.
- [ ] F26: числа не повторяются в теле.
- [ ] id вариантов уникальны, kebab_case; на них можно ссылаться из изделий (F62).

## Этап 9. Валидация и коммит

```bash
python3 scripts/sync_materials.py --check
python3 scripts/generate_lists.py
```

Коммит: `feat(материалы): material_<имя> — <название>`.

## Типичные ошибки ИИ

- Выдуман химический состав или CAS-номер (запрещено без источника).
- Два варианта с `основной: да` (допустим ровно один).
- Одна цена на все варианты (моно- и поликристалл различаются в разы).
- Химическая стойкость свободным текстом вместо 9 enum-полей.
- Свойства продублированы в теле (F26).
- Смешаны поля метаданных v10.1 и v11.0.
- `не_определён` в варианте, хотя структура известна (лень поиска) — сначала веб-поиск, потом enum.
