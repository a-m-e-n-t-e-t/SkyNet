# 08. Алгоритм заполнения карточки произведения (§9, схема v11.0)

> Карточка произведения: `фантастические данные/произведения/work_NNN.md`. Шаблон: `шаблоны/произведения.md` (в `шаблоны/`).
> Произведение — первоисточник канона: модели ссылаются на него через `произведения: [work_id]` (v9.18).

## Предусловия

1. Номер: `SkyNet-Work-<NNN>` — СКВОЗНАЯ нумерация (work_001 … work_052 …); следующий свободный номер — из `фантастические данные/_реестр_произведений.md` (§9 Phase 0.7). Не угадывать: проверить реестр и список `_список_произведений.md`.
2. Дедупликация: произведение с этим названием/годом ещё не описано.

## Этап 1. Классификация

1. `категория` — enum: `фильм|сериал|игра|книга|комикс|HTML-концепция`.
2. `название` — оригинальное название; `год` — год выхода; `режиссёр_или_автор`.
3. `источник_вселенная: SkyNet` (фиксировано).

## Этап 2. Каноничность + ОБОСНОВАНИЕ

`каноничность`: `canon|полуканон|неканон` — основа вселенной / спорные источники / апокриф. Уровень присваивается НЕ автоматически: в разделе `## Каноничность` тела — почему именно этот статус. Сомнение → `полуканон`, а не `canon`.

## Этап 3. Кросс-связи (v11.0)

1. `модели_в_произведении` — id моделей SkyNet, которые появляются: `['SkyNet-<имя>', ...]`.
2. `материалы_в_произведении` / `технологии_в_произведении` (опц.) — фантастические материалы/технологии, канон которых задаёт произведение (связь с алгоритмом 09).

## Этап 4. Метаданные — УПРОЩЁННЫЙ блок

Произведение задаёт канон, а не является артефактом разработки: поля `версия`, `статус_реальности`, `доступность`, `ии_перепроектирован` НЕ нужны и НЕ указываются. В блоке — только `источник {тип, url, проверено}`, `создано`, `обновлено`.

## Этап 5. Тело карточки

1. `## Описание` — сюжет/содержание одним абзацем; какие модели и события показаны.
2. `## Каноничность` — обоснование статуса.
3. `## Модели SkyNet в произведении` — список = полю `модели_в_произведении`, ссылки на карточки моделей.
4. `## Материалы и технологии произведения` — при наличии; = полям кросс-связей.
5. `## Источники` (реестр §9 Phase 0.7 + URL), `## Связанные произведения` (тематический указатель `_индекс_произведений.md`), `## Чек-лист`.

## Этап 6. Обратные связи

- В карточках моделей добавить этот work_id в `произведения: [...]` (двусторонняя связь).
- В карточках фантастических материалов — проверить `канон_источник`.

## Этап 7. Самопроверка

- [ ] Номер work_NNN уникален и соответствует реестру произведений.
- [ ] Данные не дублируются: метаданные — в front matter; тело — повествование (F26).
- [ ] Модели/материалы/технологии из front matter ссылаются на существующие карточки (и обратно).
- [ ] Каноничность обоснована в теле.
- [ ] В метаданных нет лишних полей (версия/статус_реальности/доступность — не для произведений).

## Этап 8. Валидация и коммит

```bash
python3 scripts/generate_lists.py
```

Коммит: `feat(произведения): work_NNN — «<название>» (<год>)`.

## Типичные ошибки ИИ

- Дублирующийся номер work_NNN (не проверен реестр).
- Канон `canon` без обоснования спорного источника.
- Нет обратной ссылки в карточках моделей (`произведения:`).
- В метаданные вшиты неприменимые поля (статус_реальности и пр.).
