# 05. Алгоритм заполнения карточки реализации модели (§12.5, схема v11.0)

> Реализация модели из реальных изделий: `результаты/модели/<модель>/<реальная|фантастическая|доработанная ии> реализация/<имя>/_index.md`.
> Шаблон: `шаблоны_реализации_модели.md` (в `шаблоны/`). Обратная ссылка — в карточке модели (`реализация_промышленная` / `реализация_ии`).

## Предусловия

1. Карточка базовой модели существует (алгоритм 04).
2. Все используемые изделия, технологии, материалы существуют (алгоритмы 01–03).

## Этап 1. Идентификация

1. `id: <модель>-реализация-<пром|ии>` (пример: `t900-реализация-пром`).
2. `тип: реализация_модели`; `базовая_модель: SkyNet-<имя>` — ссылка на карточку модели.
3. Метаданные: `вариант: промышленный|ии-улучшенный`; `версия: реальная`; `статус_реальности: real`; `доступность` — enum §32 (реальная сборка — обычно `лабораторный|ограниченный|промышленный`); `ии_перепроектирован`: `нет` (пром) / `да` (ии).

## Этап 2. Состав реализации

1. `используемые_изделия` / `используемые_технологии` / `используемые_материалы` — только СУЩЕСТВУЮЩИЕ карточки.
2. `подсистемы_покрыты` — сверить с expected_subsystems базовой модели: множество должно быть подмножеством (⊆); что не покрыто — назвать в «Ограничениях».
3. `покрытие_функций_pct` — 0–100 с обоснованием в теле (какие функции модели закрыты составом).

## Этап 3. Физическое воплощение (v6 — по одному значению)

1. `основные`: `масса_kg` (Σ масс изделий × количество), `габариты_mm {l, w, h}`, `выработка_энергии_W`, `выработка_тепла_W` (Σ тепловыделений) — номиналы конкретной сборки.
2. `наследуемые` — только `{computed_from: базовая_модель}` (lifetime_years, verification_status).
3. `дополнительные`: `цена_usd` (Σ стоимостей), `время_сборки_ч`, `уникальные_особенности` (что отличает от оригинала).

## Этап 4. Тело карточки

1. `## Целевая модель` — ссылка на карточку модели.
2. `## Соответствие канону` — насколько реализация соответствует канону; что сознательно упрощено.
3. `## Состав реализации` — изделия / технологии / материалы со ссылками.
4. `## Расчёт параметров` — таблица методики: `масса_kg = Σ масс изделий × количество`; `выработка_тепла_W = Σ тепловыделений`; `покрытие_функций_pct = доля покрытых функций`. Итоговые числа — в front matter, здесь — только методика.
5. `## Ограничения` — что не покрыто, почему.
6. `## Пути улучшения` — только для промышленных вариантов; каждый пункт — кандидат в «работа и и/» (§12.7, алгоритм 10).
7. `## Источники`, `## Чек-лист`.

## Этап 5. Двусторонние связи

- В карточке модели добавить id реализации в `реализация_промышленная` (пром) или `реализация_ии` (ии).
- Для `ии-улучшенного` варианта — блок §12.7 (предок, улучшения, real_check) по алгоритму 10.

## Этап 6. Самопроверка

- [ ] `базовая_модель` существует; обратная ссылка проставлена в карточке модели.
- [ ] `подсистемы_покрыты ⊆ expected_subsystems` базовой модели.
- [ ] `покрытие_функций_pct` обоснован.
- [ ] `используемые_*` ссылаются на существующие карточки.
- [ ] Для ии-улучшенного — блок §12.7 заполнен.
- [ ] F26: итоговые числа не дублируются в теле (там только методика расчёта).

## Этап 7. Валидация и коммит

```bash
python3 scripts/generate_lists.py
```

Коммит: `feat(реализации): <модель>-реализация-<пром|ии> — <название>`.

## Типичные ошибки ИИ

- `подсистемы_покрыты` шире expected_subsystems модели.
- Числа в «Расчёте параметров» продублированы из front matter (F26 — в теле только методика).
- `покрытие_функций_pct` без обоснования.
- Забыта обратная ссылка в карточке модели.
- `наследуемые` заполнены числами вместо computed_from.
